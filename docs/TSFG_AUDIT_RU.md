# Аудит исходного ядра и адаптера

По запросу пользователя проверяется причина отставания от DES/DAG. Корректность
результата и стоимость реализации рассматриваются отдельно.

Первичная калибровка: commit 88e988e, run 36232181823, seed 901, F1/F2 DENSE,
N=1000/10000/100000/1000000, K=10. Все 24 процесса завершились; 240 траекторий
прошли инварианты и точное пооперационное сопоставление. Калибровочные seed не
входят в H3. Внешний таймер опрашивал процессы с периодом 50 мс; внутренний
T_batch этой погрешности не имеет. Основной стенд заменён на Linux pidfd.

Первый профиль: commit 2ade199, run 36233185095, seed 902, K=100.
F1: подготовка политики 0,065 с, подготовка результата 0,048 с, исходное ядро
вместе с политикой 19,872 с. Профиль CPU относит 19,46% накопленных семплов к
fmt.Sprintf, 28,59% — к обработке границы в адаптере. Накопленные доли пересекаются
и не складываются. Подготовка графа между сценариями не объясняет основной разрыв.

На той же VM, при одинаковом полном SCHEDULE:

| N=10000, K=100 | TSFG S1 + адаптер | Минимальный C++ GRID | DES C++ | DAG C++ |
|---|---:|---:|---:|---:|
| F1, T_batch секунд | 20,19 | 0,47 | 0,68 | 0,23 |

Все эти непрофилированные результаты прошли независимое сравнение. C++ GRID
остаётся вспомогательным участником: его время не приписывается исходному S1.
Эта таблица ещё не является полным H3 на двух больших размерах.

Исправления адаптера для повторного аудита:

- Ссылки на множители станков сохраняются один раз: форматирование ID и поиск
  по строковому ключу удалены из каждого шага адаптера.
- Список одновременных завершений использует заранее выделенную память.
- После завершения всех операций прекращается обслуживание пустого остатка
  MISSION; состояние дополняется до D. Это разрешено §4.4 протокола. Пустые
  промежутки до завершения задания по-прежнему не пропускаются.

Исходные файлы ядра S1 не меняются. Старый и новый адаптеры собираются отдельно
над одним pinned source и сравниваются в порядке ABCDEEDCBA на одной VM.
После этого повторяются инварианты и точные сравнения. Эффект исправления не
объявляется до завершения этого запуска.

Запуск 36233867001 остановился до парных замеров: Git отказал в чтении старого
адаптера из-за владельца checkout в контейнере. Исправление передаёт safe.directory
только одному вызову git show и только для текущего каталога. Глобальная проверка
владельцев не отключается. Новые сравнения публикуются отдельным запуском.

Регрессия неизменного pinned S1 и Go 1.26.0 уже прошла 157 тестов в нескольких
запусках. Последующие сборки используют закреплённое свидетельство с проверкой
commit и версии Go; повторно выполняются E0, генератор, Mk01 и E1X для текущего
адаптера. Отчёт сборки явно указывает reused_test_evidence и SHA-256 свидетельства.

Все 2000 полных траекторий непрофилированной парной серии прошли независимые
инварианты и точное сопоставление. Сокращение времени составляет примерно 31–32%;
оно не устраняет разрыв с текущими эталонами. В новом профиле fmt.Sprintf перестал
быть горячей функцией. Основные расходы остались внутри универсального графового
обслуживания, строковых отображений и метрик. Эти результаты относятся к конкретной
связке Go S1 + адаптер; минимальный C++ GRID не переименован в исходный TSFG.

Автоматическая проверка повтора Ozon подтвердила отпечаток входа и восемь совпадений
метрик в двух запусках. Ни исторический диапазон scheduling-work, ни эти новые
времена не служат доказательством H3 для больших производственных заданий.
