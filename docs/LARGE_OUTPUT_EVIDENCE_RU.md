# Полный выход и хранение больших серий

Измеряемый процесс каждого участника записывает полный SCHEDULE JSONL, включая
индивидуальные начала, окончания, остатки, состояния и сроки заказов. Полный
вывод входит в T_batch и T_total одинаково у TSFG, DES и DAG.

После остановки таймера отдельная процедура читает каждую завершённую строку и
вычисляет SHA-256 канонического JSON обязательных полей из validation.checks.SIGNATURE.
Для больших scale-screen/main сохраняются эти хеши, входы, метрики, счётчики и
число завершённых сценариев. Огромные дубли полных трасс удаляются после получения
хешей; это политика хранения, а не замена измеряемого выхода на хеширование.

В другом job запускается свежий DAG на всех тех же сценариях. Его полный выход
проверяется независимыми физическими инвариантами. Только после этого хеш каждой
полной строки сравнивается с каждым участником и повтором. Для EXACT требуется
совпадение всех обязательных полей всех K сценариев и корректное завершение процесса.
Таймаут может получить только допуск завершённого префикса. Отсутствующий или
незавершённый replay не даёт допуска H3. Входы и C++ binary закреплены SHA-256.

Дополнительно на каждом наборе проверяется номинальный сценарий M0 против
опубликованных planned_start и planned_end. Малые E0/Mk01/E1X, калибровка и аудит
сохраняют полные сжатые трассы. Любое обнаруженное расхождение требует отдельного
повторения конкретного сценария с сохранением полного вывода всех участников.

Схема позволяет воспроизвести проверку каждого операционного поля, не размещая
сотни гигабайт повторяющихся трасс в артефактах. Решение H3 использует только
результаты отдельного job проверки, а не сам факт наличия контрольной суммы.
