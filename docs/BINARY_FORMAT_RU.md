# Общий вход TSFGBIN1

Формат содержит замороженное назначение и очереди; оба нативных участника читают
один файл. Альтернативы и происхождение расписания сохраняются отдельно в
operations.jsonl.gz. Время — целые тики по 0,01 секунды; шаг E2 равен 100 тикам.
Все целые little-endian. Никакого выравнивания и скрытых полей нет.

1. Восемь ASCII-байтов `TSFGBIN1`.
2. Число операций N, заказов J и станков M: три uint32.
3. N записей в порядке ID: job:uint32, machine:uint32, work:int64,
   planned_start:int64, release:int64, число предшественников:uint32,
   затем их ID:uint32. ID операции равен номеру записи от нуля.
4. M очередей: длина:uint32 и ID операций:uint32 в фиксированном порядке.
5. J идентификаторов конечных операций:uint32, по порядку заказов.

Конец файла обязателен. Planned_end выводится как planned_start+work.
Время поступления заказа совпадает с release всех его операций.
Manifest содержит SHA-256 входа, сценариев и полной текстовой записи операций.
Десять операций сохраняются в sample.json для ручного чтения.

Чтение бинарного входа входит в T_import. Подготовка S1-графа выполняется текущим
адаптером на каждом сценарии и полностью входит в T_batch. DAG сохраняет общий
топологический порядок между сценариями. Эта асимметрия раскрыта: сравниваются
конкретные доступные реализации, а не доказанная сложность классов алгоритмов.
Обязательный выход SCHEDULE остаётся одинаковым полным JSONL; хеши результатов
используются только для последующей проверки, а не вместо измеряемого вывода.
